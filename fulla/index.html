Fulla: a personal manager on Norns.

Fulla keeps one person's commitments and facts. Ask for a reminder and she brings it up when it is due, and keeps asking until it is done. She talks to her owner on Telegram, Signal or SMS and to nobody else unless told to. Each reminder is a Norns run that sleeps until it is due. She has run on the hosted instance since 2026-10-16.

Structure

What runs where

The orchestrator holds the conversation, every sleeping reminder and every parked question. The worker holds the model key, the messenger tokens and the tool code, and is stopped most of the day. Norns is the only process that is always on.

managerone conversation

Chat, the morning brief, check-ins and the nightly review all run in one standing conversation keyed to the owner, so she sees what she said earlier in the day. The scheduled ones are cron triggers in Norns that she creates and changes when asked.

reminderone run each

Each commitment is its own run of a second agent. It calls wait until due, asks once with ask_human, and closes when the owner says done. A parked run treats the next message as its answer, so the agent that chats cannot be the agent that sleeps.

channel

A run webhook tells the channel when a run parks, completes or fails. It posts the question with buttons; a tap, a reply or a reaction answers the run. Anything else typed goes to the manager. Swapping the messenger is a change to one module.

sleepserverless worker

Fulla is a serverless worker. Her tools are declared up front. When a run calls one, Norns queues the task and sends a signed POST to a wake URL. The machine starts, serves until idle, and stops. wait and ask_human are handled in the orchestrator and wake nothing, so a reminder a week out costs nothing until it is due.

machinestools-only workers

A worker on the owner's Mac serves Things, Reminders, iMessage drafts, Shortcuts and tmux; one on a Linux box serves tmux and, if allowed, a shell. Norns dispatches a tool call to whichever connected worker holds the tool. With the lid shut, a task for the Mac becomes a run parked on ask_human that the Mac worker answers when it next connects.

readersub-agent

The manager can act, and a web page can say anything, so she does not read pages herself. She hands the question to a reader agent with launch_agent. The reader can search, fetch and tell the time, but cannot act. It returns a short answer with sources.

friendsand groups

People and groups the owner allows talk to a different agent with its own conversation and a tool list that has none of the owner's facts, calendar, reminders or machines. The tool list enforces this, not the prompt.

Run it

Against a local orchestrator

Locally Fulla is a normal Norns worker that stays up and long-polls Telegram. It needs a local orchestrator, an Anthropic key, a bot token from @BotFather and your numeric Telegram id. Only that id is heard.

Say /start to the bot, then "remind me to feed the starter at 8pm". Entry points: fulla (worker and channel together), fulla-serve (the sleeping HTTP receiver used on Fly), fulla-mac and fulla-host (tools-only workers for a Mac or a Linux box). The README covers Signal, SMS, calendars and deployment.
