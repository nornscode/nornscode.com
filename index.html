Run agents that can pick up after a restart

Norns saves each run’s progress. If a worker disconnects, another can pick up the pending step. Your workers make the model calls, run the tools, and keep the API keys.

Quickstart Architecture

Run an agent locally

Use Homebrew to install the CLI and uv to run the Python worker.

brew install nornscode/tap/nornsctl
nornsctl dev
nornsctl new my-agent
cd my-agent
uv sync
uv run my-agent-worker

Once the worker connects, the Hello agent example shows how to send a message and inspect the run.

How runs resume

  1. Norns sends a task.
  2. A worker calls the model or runs a tool.
  3. Norns records the result.

Norns rebuilds run state from the log after a restart. A run can also wait there for a timer or a human reply, then continue when it’s ready. Norns supports a single-node deployment backed by Postgres.

Norns can resend a pending task with the same idempotency key. If a tool does something like charge a card, the payment service needs to honor that key to prevent a duplicate charge.
