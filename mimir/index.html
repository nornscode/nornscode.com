Mimir: a Slack knowledge bot on Norns.

Mimir answers questions about a project from the GitHub repositories and pages it is connected to. Each Slack thread is a Norns run in conversation mode. It is the reference application for the runtime and has run on the hosted instance since 2026-04-15.

01Structure

What runs where

The orchestrator holds the conversation and the event log. The worker holds the Anthropic key, the Slack tokens, the GitHub token if there is one, and the tool code. Neither side can do the other's job.

thread→ run

A Slack event arrives over Socket Mode at the worker, which sends the message to the agent with the channel and thread ids as the conversation key. Replies in the same thread append to the same conversation; a parked question is answered by the next message, with no state tracked on the Slack side.

tools

GitHub search and read, URL fetch, connect a source, store a fact, recall facts by similarity. Each is registered with a JSON schema at worker start. The orchestrator offers them to the model and records which were offered on every llm_request.

memory

A fact given with "remember this" is embedded by a small local model and written to a memories table with pgvector. Later questions search it by similarity. The memory lives as long as the table does, independent of the worker process and of the run that wrote it.

sources

GitHub repositories and URLs. There is no ingestion pipeline or index to keep fresh; a search hits the source when the question is asked and the answer cites where it came from.

stewardsecond agent

The same worker serves a second agent. A cron trigger starts it, it surveys the repositories, posts one proposal to Slack, and parks on ask_human. The wait belongs to the orchestrator, not the process: a redeploy mid-wait loses nothing, and an answer the next day resumes the same run, which can then launch_agent a coding agent.

recovery

If the worker is lost mid-search, the pending tool call is re-dispatched with the same task id and idempotency key, and the run continues from the last completed step. Between April and October the runtime was redeployed 104 times and Mimir 44 times with no run lost.

03Run it

Against a local orchestrator

Mimir is a normal Norns worker. It needs a local orchestrator, an Anthropic key, and a Slack app created from the manifest in the README. Compose brings up Postgres and the worker.

Entry points: mimir-agent (database init, worker, and Slack adapter together), mimir-worker, mimir-slack. GitHub tools work unauthenticated against public repositories; set GITHUB_TOKEN for private ones or a higher rate limit.
